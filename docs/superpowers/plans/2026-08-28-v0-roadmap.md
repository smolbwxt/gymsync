# Road to Version 0 — 2026-08-28

**Definition used here:** v0 = the first public App Store release. Every
item below is sorted by one question: does it block submission, does it
block a good first week for a stranger, or can it ride a v0.x update?
TestFlight today = master `3d85656` (consult-as-build, weeks booking,
injury severity, focus lifts, routine threads).

## A — Owner-side App Store work (blocks submission; no code)
- [ ] App Store Connect: create PRO products ($9.99 monthly / $99.99
      yearly), sign the paid-apps agreement. Everything in B waits on this.
- [ ] Privacy labels, age rating, review metadata, support URL, App Store
      screenshots.
- [ ] Two open monetization calls from the design doc: founder lifetime
      SKU yes/no; free "taste of COACH" yes/no.

## B — Monetization code (blocked on A; small once unblocked)
- [ ] M2: flip `Monetization.paywallEnabled` and wire the feature gates.
      StoreKitService, purchase/restore, and the verify-entitlement edge
      function shipped in M1 — the machinery is live-but-dormant.
- [ ] Recommendation: v0 ships PRO subscription only. Chalk packs
      (consumable rail) and creator program IAPs are v0.x — both are
      designed, neither blocks release.

## C — First-run integrity (blocks a stranger's first week)
- [ ] O1 [high]: kill the app after username creation → screens 4–7 of
      onboarding never appear again, and the Coach offer never fires.
      A first-run state machine must be resumable.
- [ ] O3 [med]: walkthrough is device-local and non-resumable; a second
      account on the same device gets no walkthrough.
- [ ] Device pass of the new consult arc — the model paths CI cannot
      exercise: close-chat voice (consequences, not readback), thinking
      row, routine-thread answers, injury severity screen, ladder feel.
- [ ] O4/O5 [low]: step numbering; a true first-run replay for QA.

## D — The Home decision (owner decision, then M–L build)
- [ ] P2.2: Home still ignores the enrolled block — `loadTodaysRoutine()`
      picks the last-used routine. The block is now the product's spine
      (consult → build → schedule → booked sessions), and the app's
      primary surface shows no trace of it.
      **Recommendation:** Home leads with today's booked session from the
      enrollment; the dead last-used path is deleted. This is the last
      big UX seam before v0.

## E — Correctness holes worth closing before v0 (small, high-trust)
- [ ] Prove `SessionRepository.upcoming()` is athlete-scoped (RLS +
      query). WeekBooker's clear step deletes sessions in the week's
      window; it must be provably unable to touch anyone else's.
- [ ] P5.1: verify RIR persistence (the one unverified claim in the
      backlog — generator computes rirLow/High; does any of it reach the
      athlete?).
- [ ] Focus-areas volume: owner decision pending (see the session note —
      the "pick two, I'll give them the volume" copy is not what the
      generator does; today a third pick is silently dropped
      alphabetically).
- [ ] Birth year: ProgramBuilder passes nil (profile never carried it),
      so youth ceilings are inactive. Read it from the account profile.

## F — Rides v0.x updates (do not block release)
- Coach/generator: cue render site (P3.3), lightDay weekday identity
  (P3.4), complexity float tilt, ladder within-rung ordering, injury
  healing path + mid-block condition applier join, focus-lift vs
  cautioned joint messaging, `CoachWizardView` deletion (hygiene).
- Grammar levers by demand: dose/prescribe (needs a who-wins rule),
  require, bookend, prefer — watch `training_rules.intent = 'unknown'`
  for real athletes asking.
- Trainer arm: T1 + client page/ledger/records are shipped; live-watch,
  COACH-for-client, notes/chat/notifications (T4/T5) are post-v0.
- Research rails: Cressey wave (1,040 videos), 12 unincorporated corpus
  lessons, block-catalog polish.
- Restyle sweep: Settings tree, Friends, CreateGroup, GroupView manage,
  Venue inner cards, Home join-code card; group-interlude recovery
  pills; screenshot-suite flakes.
- Web portal (gym seats, creator sales pages) — separate effort entirely.

## The short version
Code-side, v0 is: **M2 gates + O1/O3 + the Home decision + four small
correctness proofs + a device pass.** Everything else on the lists above
is either already shipped or explicitly v0.x. The critical path runs
through the owner: ASC products and metadata unblock B, and the Home
decision unblocks D.
